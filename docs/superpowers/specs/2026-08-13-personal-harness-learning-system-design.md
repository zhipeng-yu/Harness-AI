# 超体个人成长操作系统设计规格

- 日期：2026-08-13
- 状态：产品设计已确认，等待书面规格审阅
- 第一阶段：本机单用户个人学习网站
- 未来阶段：按需扩展为邀请制、多用户数据隔离的网站

## 1. 背景与目标

用户拥有一套共 18 章的「超体 Evolving」课程，并已取得将课程内容二次加工、向受邀用户分享的明确授权。课程聚焦 AI 时代的个人成长，核心是将 Harness AI 与 Harness Self 结合，使学习者把认知转化为现实行动，逐步构建自己的 Personal Harness System。

本项目不把课程简单搬到网页，也不建设传统的考试型学习平台。它要解决的问题是：高密度、晦涩的课程内容容易带来短期认知刺激，却难以被理解、吸收、实践和持续迭代。

第一阶段的产品目标是建立一个完全属于用户本人的成长操作系统，使每一章课程都经过以下闭环：

> 理解课程 → 联系自身 → 选择现实问题 → 设计行动 → 创建 Artifact → 实践 → 复盘 → 更新个人系统

最终成果不是 18 个“已完成”标记，而是一套由真实行动成果组成、可以长期使用和迭代的个人 Harness System。

## 2. 成功标准

第一阶段成功必须同时满足以下条件：

1. 用户可以在自己的 Windows 电脑上通过一个简单入口启动和关闭网站。
2. 首页能展示 18 章成长地图，并根据当前状态推荐下一项最有价值的动作。
3. 所有章节均可浏览，但每章的理解、行动、Artifact 和复盘状态分别记录。
4. 用户的回答、行动计划、Artifact 和复盘在网站重启后仍然存在。
5. Artifact 可以从草稿进入实践、完成复盘，并生成新版本或归档。
6. 未形成闭环的章节会提示，但不会阻止用户浏览后续章节。
7. 网站只展示加工后的学习内容，不展示课程原音频或逐字稿。
8. 更新章节内容不会覆盖或破坏用户已有的个人记录。
9. 本机数据库可以自动备份，并通过实际恢复测试证明备份有效。
10. 核心学习流程在桌面端完整、清晰、适合长时间使用。

## 3. 产品原则

### 3.1 行动优先

网站不以“看了多少”为核心，而以课程是否进入现实行动、是否产生 Artifact、是否经过复盘为核心。

### 3.2 引导而不强迫

全部 18 章可随时查看。系统提供推荐顺序和未闭环提示，但不锁章、不设置截止日期、不制造逾期压力。

### 3.3 固定内容，不做运行时 AI 个性化

所有学习者看到相同的课程讲解、练习和行动任务。课程内容在建站阶段由 AI 辅助加工并经用户审核，网站运行时不调用 AI，不产生模型调用费用。

### 3.4 忠实整理，不额外评判

加工内容以忠实表达课程原意为准。第一阶段不增加事实核验、证据等级、争议提示或独立理论扩写。听不清、缺少视觉信息或上下文不足的部分不进行猜测。

### 3.5 轻量记录

记录范围限定为章节进度、个人回答、行动计划、结构化文字 Artifact 和实践复盘。不做全面量化、不做每日打卡、不追踪睡眠、情绪等连续指标。

### 3.6 隐私优先

第一阶段完全在本机运行，不开放局域网或公网端口。未来多人版默认保持用户之间的数据完全隔离，且网站所有者不提供查看其他用户个人内容的产品入口。

## 4. 建设阶段

### 4.1 第一阶段：本机单用户版

第一阶段只建设当前会实际使用的功能：

- 本机单用户访问，无注册和登录流程；
- 18 章成长地图；
- 章节学习工作台；
- 加工后的固定学习内容；
- 个人回答与行动计划；
- 结构化文字 Artifact；
- Artifact 版本迭代；
- 实践复盘；
- 自动保存；
- 本机数据库备份与恢复。

第一阶段明确不包含：

- 原音频和逐字稿展示；
- 运行时 AI 生成；
- 事实核验；
- 注册、登录、邀请码和账号管理；
- 公网隧道或远程访问；
- 社区、互评、排行榜和用户比较；
- 文件上传和外部链接型 Artifact；
- 日历、截止日期、打卡和消息提醒；
- 内容管理后台。

### 4.2 第二阶段：邀请制分享版

只有用户决定分享网站时才建设第二阶段。预计增量功能包括：

- 安全公网隧道；
- 一次性邀请码；
- 用户名和密码登录；
- 密码重置管理命令；
- 每位用户独立的进度、回答、行动、Artifact 和复盘；
- 所有私有数据查询强制绑定当前用户身份。

第一阶段的数据模型需保留内部所有者边界，使现有数据未来可自动归入所有者账号。这个预留不得在第一阶段演变为未使用的完整账号系统。

## 5. 信息架构

网站包含四个一级区域。

### 5.1 我的首页

首页用于回答三个问题：

1. 我现在处于哪里？
2. 哪些事情还没有形成闭环？
3. 下一步做什么最有价值？

首页展示：

- 18 章成长地图；
- 当前推荐章节或推荐动作；
- 尚未完成的行动、Artifact 和复盘；
- 已形成的个人系统模块摘要。

### 5.2 18章地图

集中展示全部章节及其状态。用户可以自由进入任何章节。每章分别显示：

- 尚未开始；
- 已完成学习；
- 已制定行动；
- 已创建 Artifact；
- 已实践并复盘。

### 5.3 章节工作台

章节工作台是主要学习空间。它把每一章组织为六个连续阶段：

1. 进入本章；
2. 理解系统；
3. 照见自己；
4. 行动设计；
5. 创建 Artifact；
6. 实践复盘。

页面采用三栏桌面布局：

- 左侧：本章结构与阶段状态；
- 中间：加工后的课程内容和当前任务；
- 右侧：持续可见的个人行动摘要。

一次只推动一个明确步骤，避免高密度课程造成认知过载。

### 5.4 我的系统

这里不按课程目录展示内容，而按用户已经形成的个人系统模块归档，例如注意力系统、内容创造系统、能量管理系统或 AI 协作系统。

每个系统模块可包含：

- 来源章节；
- 当前 Artifact 版本；
- 运行状态；
- 历史版本；
- 实践复盘；
- 下一项调整。

## 6. 首页推荐逻辑

系统不使用日期计划。推荐器按照以下优先级选取下一步：

1. 继续尚未完成学习的当前章节；
2. 为已经理解但尚未设计行动的章节补充行动；
3. 创建已经规划但尚未完成的 Artifact；
4. 复盘已经进入实践、且被用户主动标记为可以复盘的 Artifact；
5. 进入推荐顺序中的下一章。

推荐器只提供一个主建议，同时保留自由导航。第一阶段不依赖后台定时任务，也不根据日期自动制造“逾期”状态。

## 7. 单章内容结构

每一章的固定学习内容包含：

1. 本章在 18 章中的位置；
2. 本章解决什么问题；
3. 一句话理解；
4. 核心结构；
5. 通俗讲解；
6. 关键概念；
7. 现实应用场景；
8. 常见误解；
9. 联系自身的问题；
10. 行动设计；
11. Artifact 模板；
12. 实践复盘问题。

每章是一套完整系统，不把内容机械拆成大量细碎课时。

## 8. Artifact 与复盘

### 8.1 保存形式

Artifact 只保存网站内的结构化文字，不支持文件上传或外部链接。

每个 Artifact 至少包含：

- 要解决的现实问题；
- 从课程采用的核心原则；
- 用户定义的运行规则；
- 可观察的成功标准；
- 实践记录；
- 复盘结论；
- 下一版本只调整的一件事。

### 8.2 生命周期

Artifact 的生命周期为：

> 草稿 → 实践中 → 等待复盘 → 已复盘 → 生成新版本或归档

不同章节可以提供不同的固定模板，但统一保留问题、原则、规则、成功标准和复盘五个核心部分。

### 8.3 版本策略

复盘不会直接覆盖旧内容。用户选择生成新版本时，系统复制上一版本作为新草稿，并保留完整版本历史。归档表示暂时停止运行，不代表删除。

## 9. 18章内容生产流程

用户将分 18 次提供课程音频。每章采用统一流水线：

1. **音频检查**：确认时长、完整性、语言和明显缺段。
2. **内部转写**：生成仅用于加工的临时文字稿，不进入正式网站。
3. **语义整理**：修正口语重复、断句和明显识别错误。
4. **缺失上下文检查**：标记“这张图”“这里”“这个界面”等无法从音频还原的内容，不自行补写。
5. **结构提取**：识别本章问题、主张、概念关系、完整系统、应用场景和行动要求。
6. **学习内容加工**：按第 7 节规定的固定结构生成章节内容。
7. **忠实性复核**：仅检查是否忠于课程原意。
8. **用户审核**：在对话中提交章节摘要、结构和待确认片段。
9. **发布与验证**：用户批准后更新正式网站，并验证页面、保存和进度行为。

音频和临时逐字稿不作为网站资产。章节经用户批准并发布后，项目工作区中的临时转写文件默认删除；用户明确要求保留某章工作副本时除外。用户提供的原始音频不由网站复制或删除。

## 10. 视觉设计

视觉方向采用“生命系统”。

### 10.1 视觉语言

- 深绿色：稳定、生命力和系统主色；
- 暖橙色：只用于下一步行动、警示和重要状态；
- 米白或浅灰绿色：长时间阅读背景；
- 清晰、克制的无衬线正文；
- 适量圆角和柔和边界表达“活的系统”，避免游戏化卡片堆叠。

### 10.2 明确避免

- 赛博神经网络背景；
- 高饱和霓虹色；
- 炫技动画；
- 积分、徽章、连续打卡等外部奖励刺激；
- 为展示数据而堆砌仪表盘；
- 为移动端压缩桌面端学习效率。

### 10.3 响应式边界

第一阶段桌面优先。手机端只保证基础可访问，不承诺在小屏完成复杂 Artifact 编辑和复盘体验。

## 11. 技术架构

### 11.1 总体结构

采用一个本地 Node.js 全栈应用，包含页面、服务端逻辑和数据访问，避免拆分为独立前端、API 服务和多个部署单元。

建议实现组合：

- TypeScript；
- React 全栈框架；
- SQLite；
- 轻量数据库访问层和显式迁移；
- 课程内容保存在版本控制内的结构化文件中；
- 个人记录保存在不进入版本控制的本机数据库中。

具体框架和依赖在实施计划中确认，但必须服从“本机简单启动、单进程、可迁移”的目标。

### 11.2 数据边界

共享课程内容与私人成长记录严格分开：

- 课程层：章节、章节版本、内容区块、问题模板和 Artifact 模板；
- 个人层：章节进度、回答、行动计划、Artifact、Artifact 版本和复盘；
- 系统层：数据库版本、备份记录和默认所有者标识。

课程更新通过稳定章节 ID 和问题 ID 关联个人记录，不能依赖标题或显示顺序作为唯一标识。

### 11.3 未来用户边界

第一阶段内部使用一个稳定的默认所有者 ID。个人数据表保留所有者字段，但应用不实现用户界面、认证或多用户管理。第二阶段加入账户系统后，将默认所有者映射为正式所有者账号。

## 12. 数据模型概念

核心实体包括：

- `Course`：课程元数据；
- `Chapter`：稳定章节 ID、序号、标题、版本和发布状态；
- `ContentBlock`：章节中的结构化学习内容；
- `Prompt`：联系自身、行动设计和复盘问题；
- `Owner`：第一阶段唯一的默认所有者；
- `ChapterProgress`：章节各阶段状态；
- `Response`：用户对固定问题的回答；
- `ActionPlan`：现实问题、行动和成功标准；
- `Artifact`：一个长期存在的个人系统模块；
- `ArtifactVersion`：不可覆盖的版本快照；
- `Review`：一次实践复盘；
- `BackupRecord`：备份文件、时间和验证状态。

删除策略优先使用归档和软删除。第一阶段不提供批量清空个人记录的界面。

## 13. 保存、备份与异常处理

### 13.1 自动保存

- 文字输入停止一小段时间后自动保存；
- 页面显示“正在保存、已保存、保存失败”状态；
- 保存失败时保留浏览器中的当前输入并允许重试；
- 切换页面前若仍有未成功保存内容，必须提示用户。

### 13.2 数据备份

- 每次课程内容或数据库结构升级前创建备份；
- 提供一个明确的手动备份入口或本地命令；
- 备份文件按日期时间命名并保存在独立目录；
- 备份保留策略在实施计划中设置合理上限，防止无限增长；
- 必须通过临时数据库执行恢复验证，而不是只检查备份文件存在。

### 13.3 故障处理

- 应用启动失败时给出可读错误与修复建议；
- 数据库迁移失败时停止启动，不带着半迁移状态继续运行；
- 章节内容格式错误时阻止该版本发布，并指出具体字段；
- 恢复操作必须先备份当前数据库，避免二次损失；
- 任何课程内容更新不得静默删除已有个人记录。

## 14. 测试与验证

### 14.1 单元测试

- 推荐下一步的优先级；
- 章节阶段状态计算；
- Artifact 状态转换；
- 新版本生成与旧版本不可变；
- 稳定内容 ID 对个人记录的关联；
- 备份命名和保留策略。

### 14.2 集成测试

- 新建回答、自动保存、重启后读取；
- 章节内容升级后个人回答仍存在；
- Artifact 从草稿到实践、复盘、新版本的完整流程；
- 数据库迁移和回滚保护；
- 备份生成、恢复到临时位置并校验关键记录。

### 14.3 端到端测试

- 从首页进入推荐章节并完成一次理解记录；
- 制定行动、创建 Artifact、开始实践、复盘并生成新版本；
- 自由跳章后首页推荐仍符合规则；
- 应用重启后完整恢复状态；
- 页面确认不存在原音频和逐字稿入口。

### 14.4 视觉验证

- 桌面宽度下三栏工作台可读且无横向溢出；
- 长内容、长回答和多个 Artifact 版本均可正常显示；
- 保存失败、空状态和未闭环提示清晰但不过度打扰；
- 深绿和暖橙的对比度满足基本可读性要求。

## 15. 发布节奏

实施顺序为：

1. 搭建完整的本机网站框架和数据闭环；
2. 用第一章加工内容完成端到端样板；
3. 验证章节更新不会损坏个人记录；
4. 用户按次提供剩余音频；
5. 每章经过加工、用户审核、发布和验证；
6. 全部 18 章发布后进行跨章节结构复核与整体验收。

第一阶段不等待收齐全部 18 章才开始建设，也不在第一版提前开发多人分享能力。

## 16. 已确认的关键决策

- 课程共 18 章；
- 产品是个人成长操作系统，不是考试课程网站；
- 采用固定学习内容，不做运行时 AI 个性化；
- 全部章节可查看，系统只推荐不强制；
- 网站不保留原音频和逐字稿；
- 忠实整理课程，不做额外事实核验；
- 用户只能提供音频，因此必须标记缺失的视觉上下文；
- 桌面端优先；
- 不做内容管理后台；
- Artifact 仅为网站内结构化文字；
- 不安排日期计划；
- 第一阶段完全个人、本机单用户使用；
- 未来按需扩展为邀请码注册和个人数据隔离的分享版；
- 视觉采用“生命系统”方向。

## 17. 设计之外的未来候选项

以下内容不是第一阶段承诺，仅作为未来可能性记录：

- 邀请制多用户分享；
- 安全公网隧道；
- 用户主动生成只读分享页；
- 课程事实核验层；
- 手机端专用复习体验；
- 经过真实使用验证后增加更丰富的个人系统模块关系。

这些候选项必须在第一阶段实际使用后重新评估，不能自动进入实施范围。
