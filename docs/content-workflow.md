# 内容制作工作流

1. 检查完整源音频，不修改用户文件。
2. 在项目内生成临时转录稿，修正断句、重复和明显识别错误。
3. 标出仅凭音频无法确认的图片、界面和演示，不猜测。
4. 先为每章梳理从问题、推理、原课案例到行动的连续主线，再按 `content/schema.ts` 整理章节。只使用音频里的案例；正文沿讲者口吻写成可沉浸阅读的讲解，相邻页面能自然承接。每页讲清一个完整意思，页数与字数由内容决定，不设统一配额。不要在阅读正文插入核验、免责、来源或“说明性例子”提示；制作边界留在审阅文档。
5. 为需要视觉辅助的页面准备直接对应当前知识点的本地插画，保存到 `public/illustrations/chapter-XX/`；同章保持统一画风，图片不承载必须准确阅读的文字。
6. 对照音频检查观点、案例与作业，通读相邻页面检查逻辑和节奏，交给用户明确审批。
7. 停止网站，运行 `npm.cmd run db:backup`。
8. 审批后发布，保持已经使用的 chapter、prompt、field ID 不变。
9. 运行内容校验、测试、lint 和 build；随后删除项目内临时转录稿，不触碰用户源音频。

恢复数据只能使用项目 `backups/` 内的已验证 `.sqlite` 文件，并显式提供 `--confirm`。不要手动移动 SQLite 的 `-wal` 或 `-shm` 文件。
