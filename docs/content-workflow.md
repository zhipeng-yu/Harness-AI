# 内容制作工作流

## 材料与版本

1. 先读项目规则、正式课程和相关审阅记录，确认本次全部章节与展示字段。
2. 逐章读取完整原材料，核对音频文件、时长、转录对应关系和补录版本，纳入最新材料。已有完整转录直接复用，缺失部分才补转录。第1—11章现有文本包位于 `artifacts/share/Harness-AI课程第1-11章文本.zip`。
3. 识别错误先结合完整上下文修正，影响意思的疑点回听对应位置。审阅记录写明核对方式、位置与结果，自动再识别和人工听审分别如实记录。不同节目的叠音要按来源辨认。
4. 画面缺失时保留口述能够说明的内容，内部记录无法确认的界面、数字与图表。资料不足的细节等待确认，补写必须有原材料依据。

## 沿原录音的讲法做删减

- 按原录音展开问题的顺序整理。保留独立观点、推理过程、关键例子、比喻、操作步骤、数字和适用条件。
- 原话已经清楚就尽量保留，只修正口语断句和明显识别错误。删除口头重复、无信息的过渡、反复强调和意思相同的总结。
- 保留例子以及从例子走到结论的解释。每段都能读出谁遇到了什么事、为什么会这样、具体怎样理解或操作。
- 删减后检查主语、指代与必要衔接，依原材料补齐。专业词首次出现时用原课解释讲清，尤其检查“顶层意图”“内部生成”“自我叙事”等抽象表达。
- 保留讲者的语气与表达力度，删除整理者加入的结构评论、泛化感悟和空泛总结。禁止自造案例、推理或练习参数。
- 禁止新增防御性表达，包括免责声明、免责前言、审查标签，以及“这不意味着……”“并非适用于所有人”“仅代表个人经验”等预防性补话。原录音中影响意思的条件和提醒忠实保留。
- 每页讲清一个完整意思，相邻页自然承接。标题直接说明该页在讲什么。页数和篇幅由内容决定，解释被压掉时应增加文字。取消固定页数、字数和每页先结论等机械结构要求。

## 落到正式字段

按 `content/schema.ts` 修改正式课程，逐项核对标题、`problem`、`oneSentence`、`explanation[].heading/body`、行动问题、反思、成果卡与复盘。练习保留原课任务、步骤、参数、完成要求和新人／已有经验者的差别，题目独立可懂。

阅读页使用开头、连续正文、行动结尾。概念解释放在首次使用处，辅助结构字段同步准确维护。正文以原课为依据，核对方式与视觉缺口保存在审阅记录。已有插画按需复用，新增图片须直接帮助理解当前内容。

修改前后比较全部 chapter、prompt、field ID 和 slug，保留原有顺序与回答关联。调整提问时保留该 ID 原来对应的问题含义。

## 每章验收

1. **材料覆盖**。按原材料顺序核对各独立观点、关键例子、因果、步骤、条件与作业的去处，在该章审阅记录保存对应范围及尚有疑点的内容。
2. **独立阅读**。从没听过录音的读者角度连读开头、全部正文、结尾和练习，确认每段在讲什么、为什么，以及怎样理解或操作。检查相邻页面的衔接。
3. **实际页面**。先绑定项目内临时数据库，再打开每章实际阅读页，逐页检查标题、完整正文、分页与前后衔接，以及目录、前后翻页和实践入口。

全部范围完成后，运行 `AGENTS.md` 列出的内容校验、测试、lint 和 build。有未完成章节、未解决疑点或失败检查时，具体记录并如实交付。

## 发布与维护

新增课程先取得用户明确审批。用户已明确要求执行的已发布课程修订，按本次要求直接完成。发布前停止网站并运行 `npm.cmd run db:backup`，按项目现有流程验证备份。

完成后同步精简 `AGENTS.md`、`readme.md`、`HANDOFF.md` 的当前状态与引用，具体制作方法仅在本文件维护。验证通过后依项目规则提交并推送。

音频、逐字稿、数据库、备份和运行文件留在本机并排除 Git。源音频只读。发布后清理本次产生的临时转录，保留用户提供的源文本包。所有写入与清理限本项目目录。
