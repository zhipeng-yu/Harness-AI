# 内容制作工作流

1. 检查完整源音频，不修改用户文件。
2. 在项目内生成临时转录稿，修正断句、重复和明显识别错误。
3. 标出仅凭音频无法确认的图片、界面和演示，不猜测。
4. 按 `content/schema.ts` 整理讲解、概念、场景、误区、反思问题、行动与 Artifact 模板。
5. 对照音频检查忠实度，交给用户明确审批。
6. 停止网站，运行 `npm.cmd run db:backup`。
7. 审批后发布，保持已经使用的 chapter、prompt、field ID 不变。
8. 运行内容校验、测试、lint 和 build；随后删除项目内临时转录稿，不触碰用户源音频。

恢复数据只能使用项目 `backups/` 内的已验证 `.sqlite` 文件，并显式提供 `--confirm`。不要手动移动 SQLite 的 `-wal` 或 `-shm` 文件。
